# 飞书知识前置检索公共标准

## 1. 定位

本标准是当前项目所有业务任务的公共知识入口，不是可选的普通 Skill。

统一顺序：

> 理解任务 → 飞书知识前置检索 → 读取可追溯知识上下文 → 调用业务 Skill → 执行任务

飞书总控由程序自动调用公共模块。当前项目内直接打开的 Codex 窗口通过 `skills/retrieving-feishu-knowledge/SKILL.md` 调用同一模块。

## 2. 第一版边界

- 只查询和引用，不创建、修改、移动或删除飞书内容。
- 不自动沉淀任务结果。
- 当前只覆盖本项目；跨项目推广需重新确认。
- 纯呼叫、在线状态等不包含业务任务的消息可以标记 `skipped_non_business`。

## 3. 允许状态

- `matched`：找到并读取了相关知识。
- `no_hit`：完成有界查询但没有可用知识。
- `degraded`：权限、网络、限流、超时或文件读取问题导致查询降级。
- `skipped_non_business`：本次不包含业务任务。

`matched`、`no_hit` 和 `degraded` 都必须继续后续任务。知识查询不是审批门禁，不得占用正式项目生产通道。

## 4. 可靠性

- 单次总时限不超过15秒。
- 最多两轮查询；临时错误最多两次尝试。
- 最多处理五个候选、读取三份正文。
- 单份摘录不超过1500字，总提示上下文不超过5000字。
- 没有读取正文的候选不能作为已使用知识。
- 不得伪造文档标题、摘录、知识空间或飞书链接。
- 日志不得包含access token、cookie、密码或其他凭据。

## 5. 引用规则

后续任务必须区分：

1. 飞书知识库原文；
2. 基于原文形成的推断；
3. 网络或其他外部资料；
4. 执政官的一般专业判断。

每条已使用知识至少包含知识空间名称、文档标题、飞书链接或token以及相关摘录。

## 6. 当前知识空间

- 老雷知识库：IP变现、发售、成交、商业模式和运营经验。
- 老雷课件知识库：课程、课件、教学方法和发售资料。
- 新媒体部：公众号、选题、传播和内容运营。
- 产品部门：产品、材料、实验、研发和数据。

具体编号和路由词以 `config/feishu-knowledge-sources.json` 为准。

## 7. 直接窗口入口

项目窗口把以下JSON通过标准输入交给：

```powershell
node scripts/run_feishu_knowledge_preflight.mjs
```

输入字段固定为 `requestId`、`text`、`summary`、`capabilityId`、`evidencePath`。任务正文不得拼入命令行参数。凭证路径必须位于项目目录内。

输出是面向后续 Skill 的知识上下文，完整凭证写入指定的 `knowledge_context.json`。

## 8. 异常与停止条件

- 缺少 `search:docs:read`：返回 `degraded`；部署验收不得宣称全文检索已经上线。
- 授权过期：允许正常刷新；无法刷新则降级。
- 网络、限流或服务端临时错误：有限重试后降级。
- 同一根因连续三轮修复仍失败：停止自动修复并保留证据。
- 任何实现试图调用飞书写入接口：立即停止，不得进入第一版。
